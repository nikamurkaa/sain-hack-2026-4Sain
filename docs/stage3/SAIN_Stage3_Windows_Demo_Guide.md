# SAIN Smart Room — Windows 10/11 · LIVE AI + local simulator

**Состояние:** код Windows launcher и CI-пакет реализованы; **нативный запуск в Windows и настоящее сквозное голосовое управление пока НЕ ПРОВЕРЕНЫ**.

## Что входит
`SAIN-Smart-Room-Live-AI-Windows.zip` — отдельная сборка GitHub Actions из исходного SHA. Содержит `START.cmd`, `STOP.cmd`, `CHECK_ENV.cmd`, Python/FastAPI backend, клиент `frontend/dist` после Vite, тестовый симулятор и исходники. **Секретов внутри нет**. Установка Python-зависимостей при первом запуске требует интернет.

## Запуск
1. На Windows 10/11 установить **Python 3.11+**, убедиться что работает `py -3.11 --version` или `python --version`. `CHECK_ENV.cmd` проверяет подготовку.
2. Из GitHub Actions workflow **Build portable Windows demo**, соответствующего последнему SHA Draft PR №24, скачать artifact `sain-windows-demo`. Из вложенного ZIP достать **SAIN-Smart-Room-Live-AI-Windows.zip** и проверить соседний `.sha256`. Распаковать весь архив в отдельную папку, не запускать из ZIP.
3. Запустить `START.cmd` → вариант **3 = LIVE AI**. Это реальный AI-провайдер, но **локальный программный симулятор устройств**.
4. Если `LLM_API_KEY` не настроен, появится **скрытый** запрос ключа. Никогда не вводить командный `api.token` вместо AI-ключа. `LLM_MODEL=gpt-6-luna`, `LLM_BASE_URL=https://bifrost.be-healthy.tech/v1` — значения по умолчанию, при наличии действующего разрешения. Исходный ключ организаторов по документации истекает **23.11.2026 в 12:00 МСК**; после срока нужен **новый разрешённый ключ**, не обход ограничений.
5. Приложение откроется на `http://127.0.0.1:4173`; backend на **127.0.0.1:8765**. В новом CMD из распакованной папки выполнить `.venv\Scripts\python.exe -m scripts.client_access dev --stay stay_test`; скопировать **временный локальный гостевой токен** только в экран авторизации.
6. Проверить плашку **LIVE AI · локальный симулятор**, выполнить текстовый запрос, разрешить микрофон, проверить транскрипт до отправки, затем использовать кнопку **Озвучить ответ** в диалоге.
7. В диалоге раскрыть **Live AI · проверить обращения** и нажать **Обновить**: счётчики показывают количество валидных ответов провайдера в текущем серверном процессе. Нуль — не подтверждение подключения.
8. Закрывать приложение через `STOP.cmd`. Повторный запуск требует новый гостевой токен; прошлые in-memory сеансы не восстанавливаются.

## Режимы
- **1 REHEARSAL:** FakeLLM + MockSimulator, только автономная репетиция. Не выдавать за живой AI.
- **2 STAND:** клиент официального стенда с отдельным разрешённым гостевым токеном; **без деплоя**, read-only финальные сеансы не меняются.
- **3 LIVE AI:** настоящий `LLM_MODEL`, реальный STT `gpt-transcribe`, TTS `tts-1`; **локальный симулятор**, без обращений к официальному simulator API.

## Возможные сбои
- `401/403` — истёк/запрещён доступ; не повторять бесконечно.
- `402` — исчерпан дневной голосовой бюджет; показать текстовый ответ.
- `413` — превышен размер файла 5 МБ.
- `429` — лимит STT/TTS; подождать допустимое время.
- Нет микрофона — использовать HTTPS или `localhost`, разрешить доступ, исправить текст вручную.
- `500/timeout` при действии — **не повторять POST** до сверки `reconciliation`; сохранение idempotency-key обязательно.
- Нативный запуск, звук микрофона, MP3 в Chrome/Edge/Firefox и STOP на Windows должны быть отдельно засвидетельствованы владельцем.

## Безопасность
- Ключ только в переменной окружения локального серверного процесса / скрытом запросе PowerShell, не в браузере, Git, ZIP, скриншотах, DevTools headers или отчётах.
- В режиме 3 гостевые и AI-ключи **разные**. Хранилище истории и модель устройств — локальные синтетические данные.
- Не запускайте официальный final `/run`, не деплойте на старый стенд и не обойдите окончание срока доступа.
