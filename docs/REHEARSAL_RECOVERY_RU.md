# SAIN Smart Room — безопасное восстановление автономного показа

**Область применения:** только локальная репетиция с MockSimulator и FakeLLM. Здесь не описано восстановление официальной финальной сессии, повторный `/run` или обход HTTP 409.

1. Держите старый проверенный Windows ZIP отдельно. Не заменяйте его новым ZIP до успешной приёмки.
2. Перед показом запустите `CHECK_ENV.cmd` и затем `START.cmd` → **1 = REHEARSAL**. Убедитесь, что `http://127.0.0.1:4173` открывается. Для проверки `/health` автономного сервера используйте `http://127.0.0.1:8765/health`.
3. Выполните в CMD из распакованной папки `.venv\Scripts\python.exe -m scripts.client_access dev --stay stay_test`, скопируйте только выданный **временный клиентский** токен в форму подключения. Командный или официальный ключ в браузер не вставляйте.
4. Для безопасной репетиции пройдите: заселение → план → номер → «Сделай попрохладнее» → ручная настройка → виртуальное время → возвращение к актуальному состоянию. Для final допустим только просмотр; демонстрацию изменений проводите исключительно в отдельном разрешённом dev/rehearsal-сеансе.
5. При пропаже сети на официальном стенде не используйте скрытые маршруты и не пытайтесь обойти 409. Переключитесь на честно обозначенную **автономную репетицию** и, при необходимости, заранее подготовленный видеоролик.
6. Если локальный backend перезапущен, старый гостевой токен становится недействительным: закройте старую сессию интерфейса, создайте новый временный токен командой из шага 3 и подключитесь повторно. Данные прежнего сеанса не восстанавливаются и не должны изображаться сохранёнными.
7. Если занят порт 4173/8765, запустите `STOP.cmd`, проверьте отсутствие других локальных экземпляров и затем повторите `START.cmd`. `STOP.cmd` должен останавливать только собственные процессы; чужие не завершайте принудительно.
8. При проблеме установки Python-зависимостей покажите сохранённое резервное видео; для первого запуска репетиции может понадобиться интернет. Если Python не найден, установите 3.11+ и проверьте через `CHECK_ENV.cmd`.

**Контроль допуска:** сервер отвечает на `/health`, новый dev-сеанс создаётся после restart, команды подтверждаются через фактическое состояние симулятора, нет обещаний управления final-гостем. Нативные тесты Windows и живые LLM/STT проходят отдельно и не подтверждены только этим документом.
