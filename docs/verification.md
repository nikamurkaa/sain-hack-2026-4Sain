## Офлайн-аудит 19 ноября

Из корня репозитория после установки `requirements-dev.txt`:

```bash
python -m pytest -q
python -m scripts.check_offline
```

Тесты используют TestClient, ASGITransport и MockTransport. Внутри прогона фиктивные значения перекрывают переменные окружения, а контекст блокирует DNS и исходящие соединения Python. Настоящие HTTP-клиенты, симулятор и модель организаторов для прогона не нужны. Ненулевой код означает нарушение контракта, ожидаемого состояния или ограничений результата.

**Локальный результат.** 128 тестов прошли. В пакете 10 гостей, 10 заездов, 60 просьб всех 19 намерений, в том числе 10 уточнений из двух реплик и 5 продолжений предыдущих просьб. Отдельные эталоны задают результат для каждого поля комнаты и класс реплики. Два домашних пояса, три температурных профиля, любимый трек и тишина, старые и новые свидетельства. Проверены HTTP 200, JSON Schema, сохранение порядка, уникальность сеансов, один запрос набора, передача входящего токена. Фиктивная модель выдаёт заданные структурированные решения. Запросы к живой модели и распознавание реальной речи в этот эксперимент не входят.

60/60 состояний и классов совпали. Пропуски и лишние изменения — 0. Для R1–R7 выдержаны 70/70 проверок, для R8 совпали 10/10 моментов отбоя. В каталоге правил версии `gen-case2-draft-2026-11-14` R8 — поправка ко времени, отдельно не оценивается. В примере карточки приведено 80 пар. Оба способа подсчёта на этом наборе дают S=1. Локальные C=1, S=1, x=1. Размер JSON около 15 КиБ. Под ограничением виртуальной памяти 512 МиБ и с привязкой к одному CPU прогон занял около 0,1 с, максимум RSS около 48 МиБ в Python 3.12. Локальный результат получен с доступными версиями библиотек. Время сети, частотный лимит реальной модели и задержка симулятора в эти цифры не входят.

Локально проверены синтаксис серверных модулей по грамматике Python 3.11, compileall, bash -n, отрицательные пути 409/429/504 и ограничение параллельности. Исполнение с точными зависимостями на Python 3.11 проверяет CI. Полный статический type-check, проверка актуальных CVE и официальный medcheck не выполнялись локально. Автоматическая проверка формулировок и значения C/S для закрытого набора остаются внешними.

### Результаты по приоритету

| Приоритет | Участок | Что проверено или исправлено |
| --- | --- | --- |
| P0 для финальной демонстрации | main.py, client-api | После финального ответа раньше выдавался изменяемый сеанс. Теперь оценочная комната открывается для чтения, сообщение возвращает 409 до модели и устройств. Dev-управление получает собственный run_id. |
| P1 | backend/clients.py | Клиент различает исчерпанный лимит и конфликт состояний по HTTP 429 и 409. Исправлен разбор необязательной статистики модели. |
| P1 | main.py | Повторное подключение больше не продлевает время жизни оценочного сеанса. Истечение dev-сеанса ограничено началом подготовки. Кеши ошибок больше не удерживают traceback исходного исключения. |
| P1 | backend/commands.py, runner.py | Чрезмерный сдвиг будильника возвращает отказ. Команды, не использующие профиль, обходятся без извлечения предпочтений. |
| P1 | tests/simulator.py | Тестовые запросы раньше начинались с одинаковых настроек каталога. Теперь симулятор использует initial_state конкретной просьбы, что выявляет ошибки сохранения будильника и других полей. |
| P2 | scripts/check_offline.py | Локальные эталоны, отчёт и запрет сетевых соединений позволяют повторять интеграционную проверку без квоты. |

Для закрытого онлайн-набора сохраняется риск ошибок понимания языка, неполной персонализации и задержек. При невозможности открыть upstream-сеанс пакет сохраняет остальные результаты в соответствии с разделом 8 карточки. Для защиты требуется согласованный способ управлять комнатой именно финального гостя. В текущем контракте новый dev-прогон открывает проживание из своего набора. Для сдачи нужны выбранный и развёрнутый SHA и форма команды.
