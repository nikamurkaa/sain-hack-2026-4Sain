# Правила и ограничения

## Предпочтения

Берём профиль и историю только нужного гостя до момента запроса, без будущих сообщений и незавершённых событий. Заполненные температура и любимые треки в профиле имеют приоритет; остальные значения извлекаются из истории. Домашние, гостиничные и разовые настройки различаются.

У каждого извлечённого факта проверяются цитата, источник и допустимость значения. Ошибочная ссылка исправляется только при единственном точном совпадении цитаты в доступной истории. Пропущенные утренние настройки дополнительно проверяются по утренним заметкам.

## Поведение

| Ситуация | Действие |
| --- | --- |
| Температура: прохладно / обычно / тепло | 17,5 / 19,5 / 21,5 °C; без предпочтений — 19,5 °C |
| Любимый звук неизвестен | Ночью тишина; для включения попросить выбрать трек |
| Звук известен, параметры нет | Громкость 15, таймер 30 минут |
| Способ пробуждения неизвестен | В расписании свет и звук; установка только времени сохраняет режим |
| «Теплее» / «прохладнее» без числа | Изменение на 1 °C |
| «Ярче» / «темнее», «тише» без числа | Изменение на 20, уменьшение на 10 процентных пунктов соответственно |
| «Выключи всё» | Выключить свет и звук; остальные настройки сохранить |
| «Как дома» / «как вчера» | Только подтверждённые настройки; «вчера» — предыдущая местная дата; без данных попросить уточнение |
| «Я проснулся» | Снять будильник и «Не беспокоить», применить утренние привычки; свет без данных — 70%, 4000 K |
| Явно недопустимое число, медицинская или посторонняя просьба | Отказ без изменения устройств |

Изменения без указанного числа ограничиваются диапазоном устройства. Если предел уже достигнут, сервер объясняет это и не сообщает об изменении. Явно недопустимое число не исправляется молча: ответ содержит допустимый диапазон.

## Расписание и выполнение

Время сна переводится из домашнего пояса в пояс отеля; при разнице от трёх часов сдвигается на час к местному времени. Без времени отбоя — 23:00, без домашнего пояса — пояс отеля.

Вечерний свет — за час до сна или с позднего заселения. Ночные настройки — при отбое, звук — через пять минут с отдельной командой выключения. Рассвет — три ступени за 30 минут до подъёма. Реализованы правила R1–R8 версии `gen-case2-draft-2026-11-14`.

У проверочных просьб отдельные комнаты с `initial_state`; уточняющие реплики рассматриваются вместе. Просьбы одного гостя обрабатываются последовательно с его историей, разные гости изолированы. В интерфейсе используется текущее состояние комнаты. Успех сообщается после проверки симулятора, повторы сообщений защищены ключом.

## Ограничения

- Сеансы и кеш в памяти одного процесса; перезапуск их удаляет. Нет постоянной базы и входа реальных гостей.
- Лимиты модели общие для команды. Обрабатываются до трёх пользователей параллельно; `/run` один, до 44 минут. Ошибочный прогон автоматически не повторяется.
- Частичное выполнение не откатывается: после ошибки нужно обновить состояние.
- Командный токен создаёт dev-прогон телом `{"case":2}`; `stage` задаёт только администратор.
- **Уточнить у организаторов:** README описывает финальный `/run`, а документация `/runs` — доступ без пакетной сдачи. `/run` реализован по README; клиентский API умеет подключать подготовленного финального гостя без повторной загрузки данных. Срок действия финального токена для действий после /run ещё нужно подтвердить.


Подтверждённый исходный профиль dislikes добавляется как цитируемый источник предпочтений. Ошибка отдельного действия в пакетном прогоне возвращает отказ. Если сеанс или сценарий создать не удалось, запись пропускается без выдуманного session_id, остальные записи продолжаются.

## Уточнения Q&A 18 ноября

- Веб-интерфейс подходит; отдельное нативное приложение не требуется.
- Речь распознаётся моделью через официальный прокси и тот же ключ. Маршрут реализован; реальный запрос с синтетической фразой проверен.
- Для R8 эксперт подтвердил предел ±1 час относительно привычного абсолютного времени; позднее заселение и отсутствие пояса обрабатываются остальными правилами. Текущие расчёты покрыты тестами.
- Для неоднозначных просьб разрешена разумная собственная трактовка. Принятые решения перечислены выше.
- Запоминание новых привычек между проживаниями — улучшение под звёздочкой. В текущей версии разовая просьба не меняет постоянный профиль.
- Механизм передачи финального гостя и токен после `/run` из расшифровки однозначно не следуют; реализация подключения подготовленной комнаты требует проверки на финальной среде.
