## Ветки

Ветка создаётся под задачу, а не навсегда под человека. `main` — общая рабочая версия, из неё идёт деплой. Изменения кода вносим через Pull Request (PR): коллега смотрит изменения, тесты проходят, затем объединяем.

| Работа | Пример ветки |
| --- | --- |
| Алексей: первый интерфейс | `feature/room-ui` |
| Николь: подключение интерфейса к серверу | `feature/frontend-integration` |
| Исправление конкретной ошибки | `fix/session-expiry` |
| Павел: требования и приёмка в репозитории | `docs/acceptance` |
| Женя: дизайн-файлы или документация в репозитории | `docs/design` |

Для работы только в Figma или внешнем документе ветка не нужна. Если Женя пишет код интерфейса, создаёт отдельную ветку под свою задачу.

Начало работы при чистой рабочей папке:

```bash
git switch main
git pull --ff-only origin main
git switch -c feature/room-ui
# Изменить файлы и сделать commit
git push -u origin feature/room-ui
```

Затем открыть PR в `main`. Новую задачу начинаем от свежей `main`. Ветки с незавершённой работой не удаляем.

`feature/case2-backend` уже объединена через PR № 1. Для новых задач она не нужна: после проверки отсутствия новых незалитых изменений её можно удалить. Код останется в `main`, история — в PR. Новую бэкенд-задачу начинаем в новой ветке.
