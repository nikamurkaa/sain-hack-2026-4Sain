Последние четыре проверки выполнены локально с ранее полученными ответами модели. Для просьб состояние устройств воспроизводилось локально. Это не новый полный прогон через настоящий симулятор. Dev-эталон использовался только для сравнения после выполнения алгоритма, не как вход решения.

## Что исправлено

- Режимы будильника light_only и sound_only приводятся к значениям устройства light и sound. Неизвестные значения отклоняются.
- Ошибочная ссылка на источник исправляется только при единственном точном совпадении цитаты в доступной истории этого же гостя. Неоднозначные и выдуманные цитаты отклоняются.
- «Вчера» рассчитывается по местному времени текущего проживания.
- Одновременные запросы одинакового профиля используют общий результат; один набор обрабатывается не более чем в три параллельных задачи.
- Короткий звуковой сценарий начинается в контрольной точке отбоя + 5 минут и завершается явной командой выключения.
- Ответы клиентского API описаны схемами OpenAPI.

## Что осталось исправить и проверить

1. В одном сохранённом ответе модель пропустила температурные, звуковые и будильниковые предпочтения. Значения по умолчанию не совпали с эталоном; ночные правила R3, R4 и R5 для этого проживания не прошли проверку.
2. В просьбе «как дома» того же гостя отсутствовала домашняя температура. Остальные доступные просьбы прошли сравнение, включая сохранение незатронутых полей.
3. Нужен полный прогон всех 38 просьб и 5 проживаний с моделью и настоящим симулятором, затем успешный /validate.
4. Не измерены итоговые время и расход токенов успешного полного прогона, нагрузка максимального закрытого набора и память при лимите 512 МБ.
5. После успешной проверки — перенос в main, проверка деплоя и клиентского сеанса на стенде.
6. Подключение интерфейса Алексея и уточнение финального способа авторизации у организаторов остаются отдельными задачами.

## Автоматические тесты

Проверяются границы истории и изоляция гостей, источники предпочтений, часовые пояса, расписание, ограничения устройств, виды команд, отказы, обработка ошибок внешних сервисов, подтверждение фактического состояния, клиентская авторизация, повторные запросы и ограничение параллелизма.

Starlette выдаёт предупреждение об устаревающей интеграции TestClient с httpx. Все тесты проходят; предупреждение не относится к запуску сервера.

```bash
python -m pytest -q
python -m scripts.check_dev --with-model
```

Вторая команда обращается к официальному LLM-прокси, передаёт историю dev-набора и расходует общий лимит команды. Она не входит в автоматическую проверку каждого деплоя.
