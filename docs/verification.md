В технической проверке симулятора использовались явно заданные тестовые предпочтения. Она подтверждает транспорт и выполнение команд, но не качество персонализации.

## Что проверяют автоматические тесты

- Разделение истории по пользователям и отсечение будущих сообщений и событий.
- Проверку существования источников и точности цитат предпочтений.
- Временные зоны, ночные настройки, рассвет и явное выключение звука.
- Допустимость чисел и сохранение незатронутых настроек.
- Все виды команд, отказы и уточнения.
- Однократную загрузку набора и передачу входящего токена.
- Раздельные сеансы проживаний и просьб.
- Ошибки модели, некорректный JSON и обрезанный ответ.
- Частичное выполнение и неопределённый исход команды без ложного подтверждения.
- Авторизацию клиентского API, изоляцию гостей, истечение сеансов и повторные сообщения.
- Повтор /run после успеха и ошибки; доступность /health во время занятого прогона.

При тестировании библиотека Starlette выдаёт предупреждение об устаревающей интеграции TestClient с httpx. Тесты проходят; на запуск самого сервера это предупреждение не влияет.

## Что ещё не подтверждено

1. Полный dev-прогон с настоящей моделью: извлечение предпочтений, распознавание всех просьб и качество ответов.
2. Успешный /validate для полного результата, созданного настоящим решением в симуляторе.
3. Расход токенов и время полного живого прогона.
4. Поведение под максимальным размером закрытого набора при лимите 512 МБ.
5. Работа интерфейса Алексея с этим сервером.
6. Финальный способ авторизации клиента: документация организаторов содержит расхождение с README.

До завершения полной проверки код остаётся в рабочей ветке. Новая серверная логика не развёрнута в main.

## Как продолжить проверку

После настройки окружения полный тест запускается командой:

```bash
python -m scripts.check_dev --with-model
```

Он использует историю из dev-набора и официальный LLM-прокси. История содержит в том числе сведения о здоровье; запуск требует разрешённой передачи этих данных сервису. Полный прогон ещё не выполнен; результаты живой проверки с моделью не заявляются.

После успешного полного теста нужно зафиксировать измеренные результаты, устранить найденные ошибки и только затем переносить реализацию в main для деплоя. После деплоя проверить SHA и HTTP-ответы.
