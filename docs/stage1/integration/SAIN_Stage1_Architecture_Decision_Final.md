# SAIN Stage 1 — Final Architecture Decision

**ADR-F1 · 2026-11-22 · Accepted for integrated local prototype; durable reattachment deferred.**
Derived from [original Stage 1 ADR in PR #19](https://github.com/nikamurkaa/sain-hack-2026-4Sain/pull/19), updated for integration-only correction.

## A. External organizer simulator: BLOCKED on documented contract

The available, authorized documentation does not demonstrate a supported method to reattach to an existing upstream session after a lost creation response or process restart. A SQLite database cannot infer remote session state or acquire an authorization that upstream does not provide. Therefore:
- One POST to create an upstream session; on lost reply/5xx outcome unknown and not retried automatically.
- Do not manufacture a session ID, probe undocumented endpoints, call official /run or bypass final read-only.
- Never reuse a cached previous token after an unverified restart as if the remote session were valid.
- A written authorized lookup/idempotency/reconciliation contract is the external gate for upstream recovery.
- No claim of exactly-once mutation, distributed transaction, or safe remote rollback.

## B. Fully local REHEARSAL: why durable SQLite is deferred, not ignored

REHEARSAL is an explicitly synthetic, loopback-bound demonstration generated by `scripts/rehearse_client.py` with MockTransport and a fresh MockSimulator. A new local session after restart is recoverable **as a new session**, not as a persisted state or last confirmed operation. Existing `ClientSession` and in-memory upstream mock are rebuilt on restart. Adding SQLite without redesigning MockSimulator state restore, token lifetime and snapshot origin would create false partial persistence. This is larger than a safe Stage 1 isolated patch and is deferred to Stage 6.

**Proposed minimal SQLite WAL design for Stage 6:**
- Versioned migrations, FK on, WAL, bounded retention, single-writer transaction boundaries.
- Tables: `stay(stay_id, guest_scope, hotel_timezone, expires_at)`, `room_session(session_id, stay_id, source, status, expires_at)`, `command(operation_id, session_id, idempotency_hash, request_fingerprint, status, created_at)`, `command_step(operation_id, sequence, device_id, target, confirmation)`, `room_snapshot(snapshot_id, session_id, observed_at, provenance, state)`.
- Unique constraints: `(session_id, idempotency_hash)`, `(operation_id, sequence)`. Transactionally reserve command key before attempting any external action; on crash, reconstruct local-only simulator from its deterministic event/snapshot log, then reconcile; never blindly resend.
- Planned Scenario separated from confirmed actual RoomSnapshot. All snapshots labeled as stale if not revalidated.
- Service secrets, bearer tokens, raw audio, raw private starter ZIP, arbitrary prompt/history and real guest PII never persisted by default. Use scoped synthetic guest IDs and redacted fields. Define retention and cascade deletion, and verify backups.
- Explicit migration, restart, crash-injection, concurrent writer and delete/reopen tests required before acceptance.

## C. Immediate Stage 1 guarantees (in-process only)

1. `Room.execute` serializes the **per-room** read/POST/reconcile sequence using an asyncio lock. Cross-room parallel work remains allowed.
2. Confirmed device steps recorded in a bounded in-memory operation journal with operation ID/fingerprint; no exposed tokens or full model prompts.
3. `done` only after matching the full observed room state; `partial`, `failed`, `uncertain`, `conflict` are different and stable under same-ID replay.
4. Journal reaching capacity fails closed rather than evicting old operation IDs and permitting replay.
5. Server API idempotency key is scoped to ClientSession, protected by session.lock; cached errors retain confirmed device IDs.
6. A lost POST response cannot be assumed failed or successful: GET snapshot is reconciliation evidence, and missing/contradictory evidence remains uncertain. No compensation or rollback is invented.
7. All scenario arithmetic uses UTC instants and outputs date-specific hotel IANA timestamps. A preview GET is a read, not room mutation.
8. Fail-closed restart invalidates all old local guest tokens and in-flight operation claims; no across-restart exactly-once promise.

## D. Downstream approval gate

Before external expert demo with real data or official API: documented partner licensing, rights to graphics/brand/source material, guest consent and retention policy, signed API scope, vulnerability review, native deployment acceptance, and independent acceptance of actual-vs-planned state semantics. No organization approval can be inferred from hackathon participation or a green CI.
