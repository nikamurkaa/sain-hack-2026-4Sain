# Подключение интерфейса к серверу

Этот документ нужен Алексею для подключения экранов. API реализовано и проверено; публикацию текущей версии на стенде подтверждает workflow в GitHub Actions.

## Основной сценарий

1. Участник команды создаёт демонстрационный сеанс из доверенной среды — например, из терминала своего компьютера.
2. Сервер загружает dev-набор, создаёт отдельный прогон симулятора и подготавливает номер.
3. В ответ приходит временный session_token. Только этот токен передаётся интерфейсу.
4. Интерфейс получает гостя, расписание и состояние устройств, затем отправляет сообщения.

Токен API организаторов и ключ модели не должны попадать в браузер. Автоматический вход реальных гостей не входит в текущую реализацию: для демонстрации используется выдача временного сеанса участником команды. Это техническое решение, которое можно заменить, когда появится продуктовая авторизация.

## Адрес и авторизация

Локальный адрес: http://127.0.0.1:8000. Адрес стенда после деплоя: https://team25.hack.be-healthy.tech.

Документация с полями запросов: /docs. Машиночитаемая схема: /openapi.json.

В запросах интерфейса передавайте заголовок:

```text
Authorization: Bearer <session_token>
```

Размещайте интерфейс на том же домене либо используйте прокси своего dev-сервера для путей /api. Открытый доступ CORS для любых сайтов не включён.

## Создание сеанса — служебный запрос

POST /api/v1/sessions. В Authorization здесь нужен HACK_TEAM_TOKEN, а не session_token. Запрос выполняется с компьютера участника команды, не из браузера гостя.

```json
{
  "dataset_code": "case2-dev-v1",
  "stay_id": "идентификатор проживания из набора"
}
```

Ответ HTTP 201:

```json
{
  "session_token": "временный случайный токен",
  "expires_in": 1800,
  "stay_id": "идентификатор проживания",
  "at": "2026-11-12T20:00:00+03:00",
  "until": "2026-11-13T07:00:00+03:00",
  "mode": "simulator"
}
```

Время в примере условное. Для работы используйте значения из ответа сервера. Сеанс действует 30 минут и исчезает при перезапуске сервера. Одновременно допускается до восьми клиентских сеансов; каждый создаёт отдельный dev-прогон.

## Запросы интерфейса

| Запрос | Результат |
| --- | --- |
| GET /api/v1/guest | Идентификатор гостя, проживание, выбранные предпочтения, их источники и значения по умолчанию |
| GET /api/v1/catalog | Устройства, допустимые значения и список звуков |
| GET /api/v1/scenario | Расписание в поле steps: время, устройство и новые значения |
| GET /api/v1/state | Последнее подтверждённое состояние комнаты |
| GET /api/v1/state?at=… | Состояние в указанное виртуальное время внутри проживания |
| POST /api/v1/messages | Ответ на просьбу и фактическое состояние после обработки |
| DELETE /api/v1/session | Закрытие клиентского сеанса, ответ 204 |

В query-параметре at знак + нужно кодировать как %2B. Например, используйте URLSearchParams вместо ручной сборки URL.

## Отправка сообщения

POST /api/v1/messages. Помимо Authorization передавайте Idempotency-Key — уникальный ключ сообщения, например UUID. При повторе после обрыва связи отправляйте тот же ключ и то же тело. Это защищает от повторного изменения температуры или будильника.

```json
{
  "text": "Сделай на два градуса теплее",
  "at": "2026-11-12T20:05:00+03:00"
}
```

Пример ответа:

```json
{
  "reply": {
    "role": "agent",
    "at": "2026-11-12T20:05:00+03:00",
    "text": "Готово. Температура: °C — 23.",
    "response_class": "done"
  },
  "state": {
    "light": {"brightness": 70, "color_temperature_k": 4000},
    "climate": {"temperature_c": 23},
    "sound": {"track_id": "track_01", "volume": 20, "timer_minutes": 0},
    "curtains": {"position": 100},
    "alarm": {"at": null, "mode": "both", "window_minutes": 0},
    "dnd": {"enabled": false}
  }
}
```

Значения условные: сервер возвращает состояние симулятора. Интерфейс не должен заранее показывать «Выполнено». Пока запрос обрабатывается, показывайте ожидание. При response_class=refused показывайте текст отказа или уточнения; это не успешное изменение устройства.

Время виртуальное и относится к датам набора организаторов. Новая команда не может быть раньше предыдущей. Указывайте дату со смещением UTC; обозначение Z не принимается. Просмотр будущего состояния через GET не переводит время сообщений вперёд.

## Ошибки

```json
{
  "status": "error",
  "code": "ACTION_UNCONFIRMED",
  "message": "Изменения подтверждены не полностью. Проверьте состояние комнаты."
}
```

| HTTP | Что делать интерфейсу |
| --- | --- |
| 401 | Сеанс истёк или токен отсутствует; получить новый сеанс |
| 403 | Нет доступа к служебному действию или внешнему сервису |
| 409 | Конфликт ключа, времени или неопределённый результат; показать сообщение и запросить состояние |
| 422 | Исправить поля запроса; ошибки формата FastAPI возвращает в detail |
| 429 | Достигнут лимит сеансов или сообщений |
| 502 / 503 / 504 | Внешний сервис не подтвердил результат; показать ошибку и запросить состояние |

При частичном выполнении нескольких команд откат не гарантируется: симулятор не предоставляет транзакций. После ошибки запрашивайте /state. Не повторяйте автоматически сообщение с новым ключом.

До 100 сообщений на сеанс. После перезапуска сервера нужно создать новый сеанс. Токен сеанса храните в памяти приложения, не в URL и не в аналитике.
