# SAIN Smart Room · проверка клиента для защиты

Дата проверки — 20 ноября 2026 г. Основа — PR №6, 0871502086da04c12cd7d1e5770298d006674af8. PR №5 и №6 открыты как draft. По истории Actions проверка на голове PR №5 завершилась успешно. Последние успешные записи деплоя относятся к main. Развёртывание головы PR №6 на стенде в рамках этой проверки не подтверждено. Рабочий процесс деплоя срабатывает на main либо по ручному запуску.

## Граница приёмки

Клиент прошёл автономную проверку интеграции с FastAPI из PR №6. Состояние устройства берётся из ответа симулятора. Для final предусмотрены подготовленный профиль и план, доступное живое чтение и подпись времени последнего подтверждения. После /run изменение именно финальной комнаты остаётся заблокированным. Решение организаторов о зачёте показа на отдельном dev-госте остаётся открытым.

## Визуальные источники и исправления

Доступ к слоям Figma ограничили исчерпанная квота MCP и отсутствие WebGL в редакторе облачного браузера. Для векторных иконок, кольца ассистента и волн использован сохранённый SAIN-Smart-Room-SVG.zip. Цвета взяты из Foundation. Четыре фотографии — фрагменты иллюстраций комнаты с приложенного листа виртуального времени, без текста и элементов управления. Шрифты Manrope и Unbounded подобраны визуально и встроены локально. Исходные семейства и точные параметры всех слоёв не подтверждены.

Двухколоночное сравнение использует кадр дизайнера слева и браузерный снимок справа. Различия видны в плотности таймлайна, расположении карточек отказа и сетевой ошибки, показе полей настроек, размере изображений и отсутствии системного iOS status bar. Название гостя, значения и статусы зависят от контракта. Мобильная кнопка диалога и подпись final/dev обеспечивают навигацию и однозначность режима. Desktop использует три области: устройства, диалог, план. На планшете план переносится вниз.

При проверке исправлены исчезновение данных при повторном выборе уже активного периода, повторная строка истории при потере подтверждения, положение поля ввода на коротком экране, место для сетевой ошибки, список при заселении и порядок иконок ответов. Снимки воспроизводятся через SAIN_SCREENSHOTS. Скрипт визуальных состояний использует управляемые HTTP-ответы. Интеграционные journey-тесты используют настоящий FastAPI с локальным симулятором.

## Результаты и приоритеты

- CPython 3.11.18, 148 passed, одно предупреждение Starlette об устаревшей интеграции TestClient/httpx.
- scripts.check_offline: 10 гостей, 60 просьб, 0 пропусков, 0 лишних изменений, R8 10/10. C=S=x=1,0 только для синтетического набора.
- TypeScript strict и production build прошли. Два unit-теста и 11 браузерных тестов в каждом из Chromium и Firefox прошли.
- P0 для финальной приёмки: нужно решение организаторов об интерактивности именно финального гостя после закрытия оценочного прогона. Только явное разрешение или официальный механизм могут закрыть этот пункт.
- P1: при разрешённом живом прогоне проверить реальный стенд, выбранный dev-заезд, микрофон компьютера жюри и время распознавания. Повторное подключение к final зависит от сохранённого в памяти бэкенда профиля.
- P2: сверить оригинальные Figma-ресурсы и типографику после восстановления доступа; проверить физический Safari и Edge. Межсессионное обучение остаётся дополнительной задачей.
