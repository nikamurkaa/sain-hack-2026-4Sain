В успешном повторном прогоне все комнаты, расписания и команды создавались и проверялись через настоящий API организаторов. Использованы 49 сохранённых ответов официальной модели для неизменённых запросов и один новый ответ — 1737 токенов. Кеш ответов находился только в локальном проверочном инструменте; в приложение и репозиторий он не включён.

Предыдущий прогон занял 205,64 секунды, сделал 34 новых обращения к модели (127119 токенов) и использовал 14 сохранённых ответов. Тогда совпали 37 из 38 просьб. Последнее расхождение — пропущенные утренние настройки — устранено дополнительной проверкой коротких утренних заметок.

Эти измерения не являются временем или полной стоимостью запуска без кеша. Полностью независимый повтор всех обращений к модели не выполнялся. Ответы модели могут различаться между запусками; успешная проверка открытого dev-набора не гарантирует результат на закрытом наборе.

Эталон использовался только после выполнения решения. Он не передавался в алгоритм или модель.

## Что исправлено по результатам проверки

- Извлечение отдельно рассматривает домашние и гостиничные настройки, проверяет всю историю по каждому типу предпочтений.
- Если в истории есть утренние настройки, а основной разбор их пропустил, выполняется дополнительный запрос только по соответствующим заметкам. Он может возвращать только группу morning; источники и значения проверяются кодом.
- Режимы будильника light_only и sound_only приводятся к light и sound. Неизвестные режимы отклоняются.
- Ошибочная ссылка исправляется только при единственном точном совпадении цитаты в доступной истории того же гостя.
- «Вчера» определяется по местному времени текущего проживания.
- Один набор обрабатывается не более чем в три параллельные задачи; одинаковые запросы предпочтений объединяются.
- Звук запускается в контрольной точке отбоя + 5 минут и выключается явной командой.

## Проверка после публикации

Workflow сначала запускает тесты, затем развёртывает приложение, сверяет SHA и проверяет ответы /, /health и валидацию /run. Полный прогон с моделью при каждом деплое не запускается. Результат публикации следует проверять в GitHub Actions.

## Оставшиеся ограничения

- Нагрузка максимального закрытого набора и пиковая память при лимите 512 МБ не измерены.
- Интерфейс Алексея ещё требуется подключить и проверить совместно.
- Сеансы хранятся в памяти; постоянная база и вход реальных гостей не реализованы.
- Финальную авторизацию нужно уточнить у организаторов: документация содержит расхождение с README.
- Starlette выдаёт предупреждение об устаревающей интеграции TestClient с httpx; 85 тестов проходят.
